# SparkleWash cloud cost and retention

Pricing checked November 5, 2026. Amounts are USD estimates for a single site and assume the shared monthly free grants have not already been consumed by other workloads in the account or subscription. Prices vary by region and account offer. Estimates exclude taxes, web hosting, logs, object operations, storage, restores, and transfer unless noted.

## Hosting decision

Start with **IBM Code Engine and Neon Free** for a short, disposable demo, as requested. The 0.125 vCPU / 0.25 GB combination is supported, but validate the API's memory and CPU needs before relying on the smallest estimate: at 240 active hours, that IBM profile is about $0.43 versus about $1.08 for Azure Container Apps Consumption at its modeled 0.25 vCPU / 0.5 GiB size. IBM's larger 0.25 / 0.5 profile is about $4.91 for the same workload. These are rate-model estimates, not quotes or observed bills. Compare measured usage and memory before making a longer-running pilot decision. Neither platform is a durable production profile until operational records, staff sessions, and photos have independent persistence. Measure latency from the site in El Salvador and use the nearest compatible Neon region. Keep the image portable and run one instance initially to bound spend. ## Neon and photo budget

Neon Free currently lists 100 CU-hours, 1 GB Postgres storage, 5 GB of public network transfer, and 5 GB object storage per project. At 0.25 CU, 100 CU-hours cover 400 hours of active compute per month; Free projects suspend after five idle minutes. Reaching the 100 CU-hour or 5 GB transfer limit suspends compute until reset or upgrade; exceeding the 1 GB database storage limit prevents writes that increase storage. Monitor compute, transfer, and storage. Free includes a 6-hour or 1 GB change-window restore bound; it is not an independent long-term archive. Use TLS with the API's pooled connection string held in platform secrets and a separate migration role. Launch lists $0.106/CU-hour and $0.35/GB-month, plus separately metered history, snapshots, and other usage. At 180 CU-hours, the Free compute allowance is exceeded. A full month on Launch at that usage is about $19.08 for compute plus $0.35 for 1 GB of database storage, before history retention, backups, object storage, or other usage. [Neon pricing](https://neon.com/pricing), [Neon connection pooling](https://neon.com/docs/connect/connection-pooling)

At 40 jobs/day × 30 days × 5 KB of relational records per job, the raw estimate is 6 MB/month before indexes, audit records, and database overhead. At two 200 KB images per job, evidence alone adds 480 MB/month and roughly 1.44 GB over 90 days. One full download per day of that 90-day history would move roughly 43 GB/month. Keep images in private object storage and put keys, hashes and metadata in Postgres. Fetch thumbnails or individual evidence on demand. Neon Free lists 5 GB of Neon Object Storage per project. IBM Cloud Object Storage currently lists a 5 GB Smart Tier Free Tier for 12 months, with monthly allowances of 2,000 Class A requests, 20,000 Class B requests, 10 GB retrieval, and 5 GB public egress; the free allowance is shared across all Smart Tier buckets in the account. This is not an always-free 25 GB tier. Treat IBM COS Free Tier as temporary, confirm region and archive availability, and keep an independent archive destination. [Neon pricing](https://neon.com/pricing), [IBM COS Free Tier](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-faq-provision), [Azure Blob pricing](https://azure.microsoft.com/en-us/pricing/details/storage/blobs/)

## Proposed retention and recovery policy

For a pilot using an existing Azure Files Hot LRS pay-as-you-go share in East
US 2, the retail meters list $0.0255 per GB-month, $0.065 per 10,000 write or
list operations, and $0.0052 per 10,000 read or other operations. An illustrative
month with 0.48 GB stored, 10,000 write or list operations, and 10,000 read or
other operations costs about $0.08 before metadata, snapshots, and transfer.
Use measured SMB operations and the actual share tier for billing forecasts.
[Azure Files billing](https://learn.microsoft.com/en-us/azure/storage/files/understanding-billing) · [Azure retail price API](https://learn.microsoft.com/en-us/rest/api/cost-management/retail-prices)

Start with 90 days of completed operational history in Neon and up to 30 days of readily available photo evidence. Confirm those provisional periods with the business before enabling automated deletion. Keep open work, unresolved disputes, financial records and inventory audit dependencies available according to their separate requirements. Hold and deletion rules should apply to replicas, archives and local caches as appropriate.

1. Schedule a server-side export of eligible closed records and related evidence. Write compressed, versioned batches by tenant and date to a separate encrypted private bucket. Include schema version, job IDs, object references, row counts and checksums in the manifest. Avoid logging plates, credentials or signed image URLs.
2. Verify the upload and run a restore into an isolated database before enabling purge. Use an idempotent archive run key and keep an online tenant-scoped archive index so the server can locate old records. Purge only exported row versions that still qualify and respect retention holds and relational dependencies. Take independent database backups and measure actual recovery time and tolerable data loss.
3. Start with an online object tier. Azure Archive has a 180-day minimum and rehydration may take up to 15 hours at standard priority (high priority can be faster and costs more). IBM Archive has a 90-day minimum, bills small objects as at least 128 KB, and restores can take up to 12 hours; IBM Accelerated Archive restores in up to two hours at a higher rate. Current IBM us-south displayed Archive rates are $0.0013/GB-month stored and $0.0209/GB restored, before requests and egress. Keep 30-day evidence online; move only data retained longer than the minimum period and when measured savings justify the restore delay and early-deletion exposure. [Azure tiers](https://learn.microsoft.com/en-us/azure/storage/blobs/access-tiers-overview/), [Azure restore](https://learn.microsoft.com/en-us/azure/storage/blobs/storage-blob-rehydration), [IBM archive](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-archive), [IBM COS pricing](https://cloud.ibm.com/objectstorage/create)
4. Use SwiftData for an authorized local read copy keyed by endpoint, tenant and account. Fetch incremental updates with a server cursor and show last sync and offline status. Distinguish a server archive event from a deletion or access revocation. Allow eligible downloaded history to remain readable offline within its local expiration policy. Purge account data on sign-out and apply deletions on the next authorized sync. A phone can lose its store and may never have synced particular records, so archive and restore must work independently of any phone.

IBM COS archive policies affect new objects only, allow one transition rule per
bucket, and cannot filter by prefix or object key. Use separate buckets for
retention classes and package small database records into larger tenant/date
batches before tiering; otherwise 128 KB minimum billing can erase the storage
savings. Archive policy execution is not a substitute for a verified restore
or a retention-hold-aware purge. [IBM archive policies](https://cloud.ibm.com/docs/cloud-object-storage?topic=cloud-object-storage-archive)

The authenticated Neon organization has a SparkleWash Free project in `aws-us-east-1`, fixed at 0.25 CU with a zero-second suspend timeout. Migrations `001_core`, `002_immutable_arrival_evidence`, and `003_archive_revisions` are applied to `main`; the `sparklewash_runtime` role has SELECT but not UPDATE on `archive_revisions`. A local production-mode API connected with the pooled runtime login and served `/readyz` with the PostgreSQL directory and archive flags enabled. GitHub now stores the rotated `NEON_RUNTIME_CONNECTION_STRING` as an environment secret; it has not been copied to Code Engine. PostgreSQL feature flags remain off in cloud because operational-store import/cutover and restore are not rehearsed. The file-backed archive remains in JSON mode; Neon-to-COS export is not wired into the API. A P-256 offline-history key is stored as a GitHub environment secret but has not been mounted in Code Engine. Existing unrelated Neon projects were left untouched. Neon CLI is usable; the Neon MCP integration is available but not connected. Keep PostgreSQL flags off until import, role separation and restore gates pass. The default API profile uses JSON and in-memory staff sessions. Photo bytes and legacy telemetry still require persistent file storage. Before a durable cloud pilot, validate live session continuity, evidence upload, archive, restore, tenant isolation and camera retries. The disposable demo resets local files when its container is replaced.
